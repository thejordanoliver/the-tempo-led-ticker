# Phase 3 — simulator-inspired LED layouts and team artwork

**Status:** implemented on the Phase 3 branch. Not yet compiled in Arduino IDE or tested on the physical MatrixPortal S3; the device and panel are still in transit.

Phase 3 extends the **Phase 2** `TempoMatrixLive.ino` sketch (Wi-Fi/API/retry behavior is retained). Phase 1's offline diagnostic sketch and the browser simulator are unchanged.

## New display features

- **Scoreboard:** 128×64 layout based on the simulator's actual 3×5 bitmap font and coordinates. Away on left, home on right; 32×32 logo slots, centered scores or `VS`, optional `#rank`, scheduled win–loss records, and bottom status. Missing artwork falls back to the team initial.
- **Ticker:** continuous horizontal 2× pixel-font scroller; shows rank (when present), teams, score or `VS`, and game status, then scrolls to the next game. Unlike the browser simulator's concatenated mega-line, each game has its own segment to keep update cost bounded on the S3.
- **Logo mode:** 48×48 logo/monogram, alternating away and home every 1.8 seconds; advances to the next game every five seconds.
- **Scheduled start times:** game `date` values in ISO8601 with `Z` or numeric offsets format as **America/New_York** 12-hour times using DST-aware POSIX timezone rules, e.g. `7:30 PM`. Invalid or unavailable dates show `SCHEDULED`. Completed games remain `FINAL`; live quarter/clock and halftime are preserved.
- Team `rank` from 1 to 98 and strictly formatted `record` fields are read from each `home` and `away` object. Long or unsupported fields are sanitized/bounded.

The S3 cannot use a browser canvas. The pixel fonts, static layout and logo bitmap drawing were ported to `TempoMiniFont.h`, `TempoDisplay.h` and `TempoLogos.h`. This is designed to approximate the simulator on **128×64**; exact color, LED timing and panel alignment must be judged on hardware.

## Compile Phase 3 (before receiving the hardware)

1. Switch to `feat/matrixportal-s3-phase3` or download the sketch folder from that branch.
2. Open **`firmware/matrixportal-s3/TempoMatrixLive/TempoMatrixLive.ino`** in Arduino IDE. Keep all `.h` files in the same sketch folder.
3. Select **Adafruit MatrixPortal ESP32-S3**. Install **Adafruit Protomatter**, **Adafruit GFX**, and **ArduinoJson 7.x** as in Phase 2.
4. Click **Verify**. It compiles *without* `secrets.h` and *without* `logos.generated.h`: `SET CONFIG` and fallback monograms are intentional until configuration and logo generation are supplied. Record the flash/RAM summary or any compiler errors.
5. When the S3 arrives, **test Phase 1 first**, then follow the Phase 2 [Wi-Fi configuration instructions](README.md) to create local gitignored `secrets.h` for a trusted LAN backend.

**Serial controls:** `1` scoreboard; `2` scrolling ticker; `3` logo mode; `m` cycle modes; `n` next game; `r` force refresh; `h` help. Rotation is normally 5 s in scoreboard/logo modes; ticker transitions to the next game when its previous line scrolls off the left.

## Generate actual team logo sprites (optional, offline)

Teams without a compiled sprite show a colored monogram, even if the Tempo API includes an image URL. To enable official artwork, run the separate **desktop build-time converter**. You need Python 3.10+ and Pillow:

```sh
python3 -m pip install Pillow
# Save an existing Tempo API response with the same logo URLs used in the simulator:
curl 'http://localhost:4000/api/games/basketball/nba?date=20261022' -o nba-scores.json
python3 tools/generate_matrix_logos.py \
  --input nba-scores.json \
  --league nba \
  --output firmware/matrixportal-s3/TempoMatrixLive/logos.generated.h
```

The date above is an *example*. For football, supply the matching NFL or CFB game response plus `--league nfl` or `--league cfb`. Only team artwork present in the supplied response is generated (typically games for that day/week), so refresh or extend the input for more teams.

For **multiple leagues**, use one combined JSON file with this structure (each `games` array comes from the matching Tempo API response):

```json
{
  "sources": [
    { "league": "nba", "games": [] },
    { "league": "nfl", "games": [] },
    { "league": "cfb", "games": [] }
  ]
}
```

Then run without `--league`:

```sh
python3 tools/generate_matrix_logos.py \
  --input combined-scores.json \
  --output firmware/matrixportal-s3/TempoMatrixLive/logos.generated.h
```

The converter crops transparent padding, preserves aspect ratio, centers within 32×32, and generates **RGB565 pixels plus an independent 1-bit alpha mask** (true white stays opaque). Sprites are compiled into program flash and scaled nearest-neighbor for the 48×48 logo view; the ESP32 does *not* fetch or decode image URLs at runtime. Up to **64 logos** are generated by default (configurable up to 128 using `--max-logos`). Each sprite occupies about **2,176 bytes** of flash before compiler overhead; watch the Arduino compile summary.

**URL and licensing notes:** HTTPS downloads are restricted by default to `res.cloudinary.com`, `a.espncdn.com` and `cdn.espn.com`; use `--allow-host host.example` only for a trusted additional provider. Redirects are blocked and image downloads are size-limited. Python Pillow cannot decode SVG URLs directly: convert SVG to PNG externally or point the input at a PNG variant. If images are already on disk, use local paths in the input with `--assets-root /path/to/assets`. Assets remain subject to the artwork owner’s terms—this repository does **not** commit downloaded logos. Generated `logos.generated.h` and `secrets.h` are gitignored.

Run converter tests:

```sh
python3 -m unittest discover -s tests/firmware -v
```

## Before finishing Phase 3

- [ ] Phase 3 Arduino sketch **Verify** succeeds (with no assets or credentials).
- [ ] Test generator Python unit tests pass; optionally generate one known team sprite and recompile.
- [ ] After delivery: Phase 1 full-grid/color test passes.
- [ ] Check scoreboard logos/monograms don't overlap scores, and rankings/records remain legible.
- [ ] Confirm the start time changes from EST to EDT correctly across winter/summer games.
- [ ] Verify ticker scroll is smooth and each game completes before advancing.
- [ ] Verify logo mode alternates both teams and rotates games.
- [ ] Verify Wi-Fi failure retains last scores, including during ticker/logo modes.
- [ ] Confirm logo flash overhead, RAM usage and long-run power/heat are acceptable on hardware.

**Limitations:** This does not provide an on-device logo CDN downloader, arbitrary user theme/settings UI, true zero-allocation rendering, or exact browser pixel/snapshot equivalence. Live HTTP fetching remains synchronous and can pause animations for up to the request timeout. Backend JSON with unknown `Content-Length` is still rejected as described in [Phase 2](README.md). Football season/week remain manual configuration.
